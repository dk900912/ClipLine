> 本文是 Windows 11 版 ClipLine 的**功能与交互验收基线**，按 Tendedero v1.8.1 源码逐项拆解，不是 README 的转述。
>
> - 基线版本：`v1.8.1`，提交 `6df2cfe`，Release 说明：「Images from a watched folder hang whole」。
> - 事实来源：`README.md`（中英）、`Sources/Tendedero/*.swift`、`Resources/*.lproj/Localizable.strings`、`LICENSE`、Release Notes。
> - 引用格式 `[源码: 文件名]` 表示该结论直接来自该文件，常量为源码字面量。
> - 标记：`✅` 可 1:1 复刻 · `⚠️` 需平台等价实现 · `❌` Windows 上不存在对应能力（见 `03-windows-adaptation.md`）。

## 1. 应用形态与生命周期

- [ ] `A-01` ✅ **无主窗口、无任务栏按钮**：`NSApplication.setActivationPolicy(.accessory)`，`main.swift`。Windows 对应：托盘常驻、无主窗体、任务栏无按钮。
- [ ] `A-02` ✅ **单实例**：重复启动只激活已有实例，不新建绳。
- [ ] `A-03` ✅ **登录时打开**（菜单开关）：macOS `SMAppService.mainApp.register()/unregister()`；失败弹窗「无法更改登录项设置」。Windows 见 `03` §14。
- [ ] `A-04` ✅ **退出**：菜单「退出 ClipLine」，退出时还原被接管的系统截图设置。
- [ ] `A-05` ✅ **异常退出也还原设置**：监听 `SIGTERM / SIGINT / SIGHUP`，`DispatchSource.makeSignalSource` → `Inbox.restore()` → `exit(0)` `[源码: AppDelegate.swift]`。
- [ ] `A-06` ✅ **首次运行欢迎**：`UserDefaults "welcomed"` 为 false 时，强制展开绳并 pin 住 **5 秒**，显示空态提示「截个图，它就会挂在这里」；若 5 秒内已有图片则不收起 `[源码: AppDelegate.swift / LineView.swift]`。
- [ ] `A-07` ✅ **首次运行询问是否接管截图**：启动 **1.2 秒后**弹出，且只问一次（`"inboxOffered"`）；两个按钮「开启 / 以后再说」，选中「开启」才改系统设置 `[源码: AppDelegate.swift / Inbox.swift]`。
- [ ] `A-08` ✅ **状态恢复**：启动时从持久化恢复上一批仍在的文件路径与固定状态；启动时若有保留照片，自动 `comeDown(on: nil)` 展示一次 `[源码: AppDelegate.swift / Line.swift]`。
- [ ] `A-09` ✅ **接管设置可回滚**：开启时先备份原值到 `"inboxSavedSettings"`，关闭/退出/崩溃恢复时写回；避免把自己的值当成「原值」 `[源码: Inbox.swift]`。

### 2.2 绳子与绳结

- [ ] `V-07` ✅ 绳为抛物线：`sag = min(30, width × 0.018)`，`ropeY(x) = 10 + 4·sag·(x/w)·(1−x/w)`，`ropeTop = 10` `[源码: LineView.swift]`。
- [ ] `V-08` ✅ 三层描边：阴影 `black 0.22 / 1.4 pt / y+1.2 / blur 1.2`；主体 `white 0.55 / 1.2 pt`；高光 `white 0.45 / 0.4 pt / y−0.35`；两端用渐变遮罩淡出（0→0.08 透明到实，0.92→1 实到透明）`[源码: LineView.swift]`。
- [ ] `V-09` ✅ **绳结**：仅当存在固定照片时出现；7×5.5 灰色椭圆 + 两条 1 pt 松散线头；位置在最后一张固定照片与下一张之间（无下一张时半个间距外）`[源码: LineView.swift]`。
- [ ] `V-10` ✅ 固定照片挂在**绳结左侧**，普通照片在右侧；固定区留出的空位也算数，直到指针离开后空隙闭合。

> **v1.4 实现状态（2026-11-05）**：`V-09` 绳结几何与显隐条件已按本条落地（`RopeCanvas.DrawKnot`：

> 另有三处**有意偏离**：绳结左侧绳段染淡靛蓝、固定卡加靛蓝描边 + 淡蓝底、绳结加 1px 羽化 ——

> `docs/09` §12.2。真实鼠标点击验证（固定 → 绳帧变化 → 取消固定 → 绳结消失）与像素级

### 4.2 菜单结构（每次打开**重建**，`autoenablesItems = false`，各项自报可用性）

| 序 | 菜单项 | 类型 / 条件 | 行为 |
|---:|---|---|---|

| 5 | 接管截图 | 复选 | 切换 Inbox |

## 13. 验收口径与已知「不可 1:1 对齐」清单

**「100% 对齐」的严谨定义**：用户可感知的**功能集合、交互结果、状态时序、视觉参数**全部对齐；系统私有能力的实现路径允许替换，但必须在验收清单里逐条声明等价方案与差异。

| 编号 | macOS 能力 | Windows 现实 | 处理 |
|---|---|---|---|
| `N-01` | 力感应点按（Force Click stage 2） | 无系统级压感；仅触控笔有 `WM_POINTER` 压力 | 中键 / 笔压 / 可配置长按组合，写入设置（⚠️） |
| `N-02` | 菜单栏中间 1/3 热区 | 任务栏默认在底部、顶部没有系统菜单栏 | 屏幕顶边中间 1/3 的热条；任务栏置顶时改为任务栏空白中段（⚠️） |
| `N-03` | 改 `com.apple.screencapture` 接管截图落盘 | 无用户级「截图目标目录」设置 | 剪贴板监听 + 监视默认截图目录/录屏目录（⚠️） |
| `N-04` | `kMDItemScreenCaptureGlobalRect` 捕获区域 | 无该元数据 | 从剪贴板图像 + **主屏坐标**推算；可选自带截图热键时记录真实选区（⚠️） |
| `N-05` | Quick Look / Markup 共享扩展 / AVPlayerView 修剪 | 无对应系统扩展 | 自绘预览窗 + 自研标注编辑器 + MediaFoundation 修剪（⚠️） |
| `N-06` | Finder 服务「挂到 Tendedero」 | 需 Shell 扩展 | MSIX 稀疏包的 `IExplorerCommand` 右键扩展（⚠️） |
| `N-07` | Spaces / 全屏 Space type 4 | 虚拟桌面 + 全屏窗口，无公开等价 API | `IVirtualDesktopManager` + 前台窗口矩形/`SHQueryUserNotificationState`（⚠️） |
| `N-08` | `trashItem(at:resultingItemURL:)` 可拿到回收站路径 | `IFileOperation` 不返回回收站路径 | 自有软删除索引保证撤销；系统回收站拖放交由 Shell（⚠️） |
| `N-09` | 系统音色 Tink / Pop / drag to trash | 音色不同 | 自带等价音效资源或映射 Windows 系统音（✅ 行为对齐） |
| `N-10` | `⌘` 键体系 | 无 | 统一 `⌘→Ctrl`、`⌥→Alt` 并在菜单显示 Windows 符号（✅ 行为对齐） |
| `N-11` | 多显示器 / 每屏 DPI（`screenUnderPointer`、`NSScreen.screens`） | **v1 明确范围外**：本地无多屏测试条件 | **不实现、不测试、不承诺**；只保证主显示器 + 单一系统缩放；原 `V-38` 删除（主动范围裁剪，非平台能力缺失） |

> 结论：**单屏范围内功能层面可以做到 100% 对齐**（每一项都有对应功能与验收标准）；**实现层面有 10 项必须走平台等价路径**，其中 `N-01` 受硬件限制无法做到物理一致，只能做到交互结果一致。另有 `N-11` 是用户主动裁剪的 v1 范围外项——因此「100% 对齐」的口径为**单屏范围内 100%**，不含多显示器与每屏 DPI。详细方案见 `03-windows-adaptation.md`。
